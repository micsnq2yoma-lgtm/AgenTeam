# IM 切换项目与多项目通知：讨论记录

状态：**评估阶段，未开发，未决策。** 本文只记录评估与待决问题；开发前须由用户拍板（CLAUDE.md：新增状态 owner / 通信模式须先讨论架构）。

## 1. 需求

1. 在 IM 对话框里直接切换项目，不必重新绑定机器人。
2. 用户有多个并行项目时，机器人如何通知用户。

## 2. 现状（评估依据）

- 机器人（Channel）属于一个助理（Agent），助理属于一个项目；新会话都在该项目目录下按该助理模板创建（`src-tauri/src/im/team_ai.rs` 的 `birth_for_peer`）。
- 同一凭据同时在两处连接会冲突，所以换项目目前只能到另一个项目重新配置，并停掉原项目的渠道。
- 数据结构已部分支持：`PeerSession.workspace_path`（`src-tauri/src/im/types.rs`）按聊天记录目录并随 health 存盘；`/new` 先读该聊天的目录再退回默认（`agent_channel.rs` 的 `/new` 处理）。目前没有入口把它设成别的项目。
- 默认"会话目录 = 机器人所属助理目录"的地方：`/model` 校验（`src/server/routes/im-model-selection.ts` 的 `Session workspace does not match Agent`）、选模型后写回所属助理默认设置、默认设置变化提醒、Team AI 聊天专属配置。
- 任务通知：`ConversationRef {channelId, sessionKey}`，经该聊天**当前绑定的会话**转述（`specs/tech_docs/im_integration_architecture.md`「Task 通知的稳定地址与发送 owner」）。Heartbeat 用 `lastActivePrivateTarget`。

## 3. 方案

### A. 每个聊天各自切换（评估推荐）

私聊发 `/project`，编号列表，选后在目标项目目录下按目标助理模板新建会话并转交该聊天绑定（复用 `/new` 与 handover 流程，同一 per-peer fence）。机器人仍属原项目，仅负责收发。

需要处理：
1. 新增 `/project`（仅私聊）。
2. 会话身份跟随**会话目录所属助理**，不跟随机器人：`/model`、`/status`、默认设置提醒、Team AI 聊天专属配置都改为按会话所属项目查助理。
3. 主动推送归属（见 §4）。
4. 桌面端：项目 2 的会话列表出现"来自项目 1 机器人"的会话；桌面接手需允许跨助理接手该聊天绑定。
5. 安全：IM 会话默认最高无人值守权限，`/project` 等于让聊天进入任意项目。建议项目级开关"允许从 IM 切换进来"（默认关），且仅白名单私聊用户可用。
6. 更新 `im_integration_architecture.md` §2、§4，补切换、回切、并发、重启恢复、越权拒绝测试。

### B. 一键把机器人搬到另一个项目

命令触发：停止连接 → 机器人配置从助理 A 移到 B → 重新启动，复用 stop/start 流程。改动小；缺点：该机器人所有私聊与群一起切走，原项目历史绑定断开。仅单人、单机器人、不进群时效果接近 A。

## 4. 多项目并行时的通知（针对 A）

必须改的规则：**通知不能经"当前会话"转述**。否则切到项目 2 后，项目 1 的任务结果会交给项目 2 的助理转述，缺上下文且写进错误对话。改为**谁产生通知，由谁自己的会话发出**。

推荐：
1. 一个私聊只有一个"当前项目"；后台项目只在 完成 / 失败 / 需要决定（含权限确认）/ 定时任务结果 时主动发消息，开头标项目名，不发过程与流式输出。
2. 引用回复通知 → 只交给发出通知的项目，当前项目不变；不引用 → 当前项目；权限与结构化提问按请求编号回答，提示里加项目名；平台支持按钮时附"切换到此项目"。
3. 每项目通知级别：全部 / 仅关键事件（默认）/ 静音；可选汇总模式；`/projects` 查看各项目状态与未读数。
4. 可选（第二阶段）：一个项目一个群或话题。需各平台接入层支持话题编号，**尚未核实**。

需新增：聊天的"关注列表"（随绑定存盘，仅开启 IM 切换的项目可加入）；通知由产生者会话发出；平台消息编号 → 会话映射（有上限与过期，如 200 条 / 7 天）；`/project`、`/projects`、通知级别设置，以及规范与测试。
