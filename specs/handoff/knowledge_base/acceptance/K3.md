## 独立复核

验收者另用 JavaScript 的 UTF-16 视图、UTF-8 字节切片与 ICU 字素边界核对全部 16 份 golden，共 25 块，其中 10 个非 ASCII 区间。独立重算的 ID、正文预算、区间和 PDF 页码 1、2、4 与预期匹配。切块性能与生产纯函数源码逐文件比对。引用用例用真实持久化来源经 Tauri mock transport 调正式命令。

默认用例使用隔离路径并离线执行。性能准入单独用 release crate 执行；带正式 Document Worker、PDFium 和 OCR 的 K3 补充用例继续分池。本轮现有 CI 通过真实 Markdown/TXT 导入和遗留 `chunking` 恢复满足 K3 范围。五类资料摄取后可检索的验收归 K4。

D5 至 D9 按差异逐项审查通过。超限字素测试保留输入原件和托管 Markdown。索引和 CLI 权限入口在后续任务接入。Store 复用现有文件读取与提交 helper，引用与恢复继续走既有 IPC。新增的表格定位文案经两套 i18n 模板，TS 与 Rust 的错误码一致。无新增 lint 豁免，认证与发布工作流未参与本次测试。

### 实现边界

- 行号和列号从 1 起算，列按原文的 Unicode 标量计数。UTF-8 字节偏移从 0 起算。固定位置以原文为准，即使前文有中文、emoji 或 CRLF，调用方也能定位到同一个字素。`reports_the_start_of_an_unsplittable_grapheme_in_any_markdown_context` 覆盖表格、标题和正文。
- 同一表的首块保存列目录。整张表的截断提示指向表的首块，超长列名的提示指向该列名开始的表头块。一个列名跨块时，以目录中的原文字节范围重组完整列名。`huge_header_preserves_source_and_column_directory_across_multiple_chunks` 验证列目录；`ipc_opens_the_first_table_header_chunk_and_reports_an_outdated_fragment` 走正式 Tauri 命令。
- 60% 按续分块的正文容量验收。允许末段自然结束；不通过重复正文来填满它。一个总宽度未到 250 token 的表头也可能含 49 token 的单列，重复显示时保留全部列并缩写该列名。`a_1001_token_cell_reserves_capacity_and_keeps_the_actual_tail`、`an_early_sentence_boundary_cannot_leave_a_short_nonterminal_cell_part` 和 `a_narrow_repeated_header_also_uses_the_shared_long_column_name` 覆盖这三种情况。
- K3 已发布的 Markdown 是持久来源。切块和片段解析核对内容摘要及当前作业；派生索引在 K4 接管。信息不足的旧作业记录可缺省 `position`。超限字素的失败位置则随作业持久化，且不会挡住下一份资料。
