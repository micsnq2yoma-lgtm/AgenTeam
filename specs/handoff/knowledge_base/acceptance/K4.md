## 独立验收与探针

独立验收者用 Windows 上完整应用的 libtest 二进制单独运行 AC-K4-1 和 AC-K4-2。二进制来自 `d371122f`，索引、schema、tokenizer 与测试 fixture 在最终候选中保持一致。验收者另写只读脚本，分别观测真实提交的四文档和 64 文档索引，核对正文分词器、库隔离字段及候选规模。应用的 libtest 以用例为输入，查询由各用例运行。

- AC-K4-1 用 `跨境物流`、`BLUEBERRY`、`跨境物流 blueberry` 和摘要词 `wildflower`，结果均为 A 库的一条引用，且英文摘录包含正文尾部的 `blueberry`。实际索引正文、前缀和标题使用中文分词器，范围及筛选字段使用精确分词器。
- AC-K4-2 两库使用相同的来源 ID 和部分片段 ID。对各库分别查询 `lychee`，实际返回 A 库的一条引用和 B 库的三条引用。空范围与正文和摘要同时命中的场景也由独立验收者复跑。
- Windows 在原生应用测试通过后因再次编译覆盖了已嵌清单的测试程序，缺清单的程序未进入 libtest。独立验收者对提交 `45939a34` 的官方测试产物核对 SHA-256 `98839ab1976dbb508794b06cdd9efbc6c88b09b9dc13ba82ea3a79256d1f3952`，在隔离副本恢复同一份应用清单后，索引六项、原子写耗尽、新增待删除用例分别 6/6、1/1、1/1 通过，原八写者并发用例逐次 64/64 通过。下一轮 CI 专项复用已嵌清单的同一个程序。
- 本机已有资源的五格式测试曾在 DOCX 断言失败。独立验收确认转换正确，标题为 `Office orchard`，实际正文为 `The test orchard has three trees.`。用例改查正文后通过。文字 PDF 的两行文字均转换为 Markdown 标题，K3 的纯标题快照产出零个片段。独立 Windows 原生转换确认扫描 PDF 有 `SCAN ORCHARD` 正文，OCR 页数为 1。另用常规段落的合成文字 PDF 核对同一 Worker 确实保留正文，OCR 页数为 0。纯标题文档的检索行为待决定。
- 静态审查对照知识库 owner 和索引路径，核对单写者、提交顺序、路径 helper、错误处理及 scope 先于排名的约束。红线未发现违规。此阶段无 UI 改动，手动 App 截图不适用。
