## Windows 和崩溃恢复

- `knowledge_refuses_a_redirected_source_directory` 和 `knowledge_refuses_a_redirected_library_directory` 用原生 NTFS junction 替换来源或库目录，检查读取、删除和外部文件内容。`knowledge_library_deletion_preserves_a_nested_redirect_target` 删除含嵌套 junction 的库并逐字节读取外部原件。
- `knowledge_unregistered_library_remains_invisible_after_reopen` 涵盖已写入及随后截断的未登记库数据、重开和继续建库。K1 保留未登记目录供恢复，分配新 ID 时避开现有目录，占用空间是已知取舍。
- `knowledge_invalid_ids_are_rejected_before_opening_the_store` 覆盖尚未创建的数据目录；八个接收 ID 的入口遇到非法输入后该目录仍不存在。`knowledge_rejects_path_traversal_in_library_and_source_ids` 检查已初始化 Store 和外部文件。
- 最初的 Windows 复跑在 Cargo 重新链接后以 `STATUS_ENTRYPOINT_NOT_FOUND` 退出，知识库用例尚未开始。复验使用相同 crate 构建出的原生测试程序，嵌入 Tauri 应用 manifest 后分别执行 `workspace_files::` 和 `knowledge::`。[原始运行](https://github.com/micsnq2yoma-lgtm/AgenTeam/actions/runs/44906790543) 和 [原生复验日志](https://github.com/micsnq2yoma-lgtm/AgenTeam/actions/runs/44908004811/job/136857616068)。
