# K2 摄取与转换验收

分支 `feat/kb-k2-ingest`，基于 K1 `dbe9c2c0`。规范变更在 `57a33b8d`，摄取实现与五类真实输入在 `569d5284`，两项独立验收探针和转换产物目录交接在 `61041cf9`，退出超时的修复与回归测试在 `24757ae1`。

## 交付和偏离

- Tauri 摄取入口按文件返回接收或拒绝结果。KnowledgeStore 持久化原件、作业和转换状态，从同一受控副本重试。Office 和 PDF 交给应用已有的 DocumentProcessingManager。
- 按用户决定修订任务文档、PRD §6 和技术文档。K2 在原子发布 Markdown 与资产后停在 `chunking`。K3 完成切块后才提交 `ready`，K4 单独报告可检索状态。
- 取消和失败时保留托管原件供重试。退出时先把排队及运行中的转换持久化为 `interrupted`，再等工作线程交还暂存目录。恢复不会改动用户提供的原文件。

## 独立验收结论

在 `24757ae1` 上，AC-K2-1 至 AC-K2-8 通过，D1–D3 和 D5–D9 通过。**D4 打回。** 受影响的共用 AnyDoc 模块通过 31/32。命令 `app_lib-69d433f65b828703 document_processing::` 并行和加 `--test-threads=1` 的串行复跑均在 `source_copy_rejects_same_inode_same_size_mutation_before_admission` 失败。测试期望返回 `DOCUMENT_SOURCE_CHANGED`，实际取得新正文的摘要。验收者保留了两次原始日志。

`specs/tech_docs/document_processing.md` 承诺检测同 inode 等长改写。现有文件版本由大小和时间戳构成，无法识别两个元数据快照完全相同的正文更改。K2 复用了这个 owner 的复制函数，因此该模块的失败计入本次验收。用户已指定从 main 分叉点单独建立 `fix/anydoc-same-tick-rewrite`，修复验收后将 K2 rebase 到其上，重新运行完整受影响套件。
