# K5 会话知识库 CLI 交付与验收

分支 `feat/kb-k5-cli`。实现提交 `29e05039`、`fa57ea0c`、`5d2287b8` 和 `173dea5681e31cad2f32158fad54d1cd021baf35`。以下本机证据对应最后一个实现提交。

## 交付

- `myagents kb` 提供列表、检索、片段读取、原文分页、文件导入、元数据修改和任务状态。Admin 用统一响应封装转发，Rust 从管理进程代际与 Session 快照裁决库范围。
- TaskStore 持有内部整理任务绑定，TaskScheduler 确认当前运行队列。Store 发布写入时重新校验权限并短暂保留执行凭据。写锁忙返回可重试错误，执行已取消或身份不符返回拒绝访问。
- 原文分页保留完整 UTF-8 字符，游标绑定会话、进程代际、源内容版本和选择范围。普通片段输出转义边界字符。
- 按确认方案，K5 实现内部整理任务绑定，K8 接入创建和调度。知识库登记在官方 CLI 工具表，Session 库绑定决定使用范围。Windows 绝对工作区路径采用规范拼写，相对路径也可使用。工作区导入使用只共享读权限的原文件句柄。

K5 在发布前重读 Session 快照，持有进程与执行凭据的 guard。K6 接入 Session 级修改时需一起验证改绑和 Store 发布的并发顺序。

本机使用 Windows GNU 备用工具链和 Rust 自带链接器。Opus 的本机临时构建采用上游提供的 CMake 选项关闭 AVX2，以兼容本机旧 GCC。基线与候选使用相同配置。两项既有真实文档资源测试在 K4 的资源验收中另有执行证据。

独立验收者使用普通 Windows 进程权限和独立临时目录复跑同一二进制，结果为 97、1、172 项通过。二进制（已嵌入 manifest）的 SHA-256 为 `a7369561bb0c9fa6fef33093407a0674d3c2ff652a5ff998899e075ad83dbd23`。独立从两份原始 Clippy JSON 重算得到相同差集。首次沙箱运行的临时目录初始化出现 `KB_STORE_UNAVAILABLE`，正常 Windows 权限复跑通过。
