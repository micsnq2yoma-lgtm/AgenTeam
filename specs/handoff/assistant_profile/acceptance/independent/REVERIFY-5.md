# AgenTeam Windows 独立复验（REVERIFY-5）

2026-11-23。复验对象为 `dev/section-edit-replace-starvation` 的 `f2cb6d9b5889ab63933705f1a452173204aafae1`。报告分支为 `acceptance/memory-reverify-5`。按 `acceptance-plan.md` 第 0 节、`REVERIFY-4.md` 和目标提交技术说明的「第五轮 Windows 复验（W1/W5）」执行，仅运行脚本。

## 用例结果

| 用例 | 结果 | 证据 |
| --- | --- | --- |
| W1（S1-C） | 通过 | 每种 Python 无读取 40/40、持续读取 20/20。600 个写入进程中退出 0 为 120 个，退出 2 为 480 个，退出 5 为 0 个。120 轮最终字节均与唯一成功者预期一致。 |

## W1 并发与读取压力

沿用上一轮的合成 CRLF 基线，SHA-256 为 `dc0e72fc9c2974d415e8d324814220c8fcae2bcf3f6c0bde11fc2bb382fd10e5`。每轮五个写入进程各用不同且实际存在的 TEMP 和 TMP，在同一文件信号下开始，对同一基线哈希提交不同作者标记。夹具通过 `runpy` 执行检出的原版脚本。

## W2 目录 ACL

用 `icacls /deny` 对夹具目录拒绝当前用户的 `FILE_ADD_FILE`（`WD`，无继承）。逐次确认现有目标可读写，创建探针文件被拒绝。四次添加和移除拒绝 ACE 均退出 0。每次目标最终 SHA-256 均为 W1 所列基线。

## W4 持锁与强杀

另起 Python 进程用 `msvcrt.locking` 锁住旁置文件的第一个字节。写入用 `SECTION_EDIT_LOCK_WAIT=1` 等待锁，返回时持锁者仍存活，目标 SHA-256 保持基线。用 `Popen.kill`（Windows TerminateProcess）强杀持锁者并等待其退出，再发起一次写入。

## W5 测试夹具回归

```text
node --test scripts/section-edit.test.mjs scripts/memory-skills.test.mjs scripts/proactive-skill.test.mjs
```

每次运行前用 PATH 选定解释器。默认组从父进程环境移除 `PYTHONUTF8` 与 `PYTHONIOENCODING`，探针实测区域编码为 CP936，3.7.1 的 stdout 报告 cp936，3.12.13 报告 gbk，两者的 UTF-8 模式均为 0。显式 UTF-8 组在父进程设置 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`，探针实测输出为 UTF-8。测试文件自行设置 Python 子进程编码。

| Python | 父进程编码环境 | 退出码 | 通过 | 失败 | 跳过 | 耗时（秒） |
| --- | --- | --- | --- | --- | --- | --- |
| 3.7.1 | 默认 CP936 | 0 | 39 | 0 | 3 | 15.406 |
| 3.7.1 | 显式 UTF-8 | 0 | 39 | 0 | 3 | 15.406 |
| 3.12.13 | 默认 CP936 | 0 | 39 | 0 | 3 | 14.610 |
| 3.12.13 | 显式 UTF-8 | 0 | 39 | 0 | 3 | 14.500 |

三个跳过均由测试在 Windows 上主动标记，分别为一个规则枚举符号链接用例和两个 section-edit 符号链接用例。W3 已直接验证同名、异名链接及共享锁。上一轮的中文输出、持锁清理和 Python 3.7 模拟 `os.open` 三项夹具故障均未再现。

## 新缺陷、阻塞项与结论

- 本轮未发现新缺陷。
- 无阻塞项。W3 的初始创建权限限制已通过只提升夹具创建进程解决。
- 本轮通过。W1–W5 和四份磁盘副本的 SHA-256 检查均通过。W1 在指定 Windows 负载下未再现 S1-C，上一轮的三类 W5 夹具问题均未再现。共享探针确认读句柄会阻挡替换。W1 结果验证了抖动和预算的组合改动在指定负载下的表现。
